# TON XMSS Wallet — постквантовый кошелёк для TON

[English version](README.md)

Смарт-контракт кошелька для TON, где траты подтверждаются **одноразовыми подписями на
хешах** (WOTS+ в дереве Меркла в стиле XMSS), а не Ed25519. Безопасность держится только на
SHA-256, поэтому кошелёк остаётся защищённым даже от квантового компьютера, который сломал бы
любой стандартный TON-кошелёк. В комплекте TypeScript SDK, создание кошелька одной командой,
CLI-скрипты и тесты.

> ⚠️ **Экспериментальный, аудита не было.** Проверен в `@ton/sandbox` и в тестнете. Комиссия
> ~0.25 TON за операцию, есть известные проблемы — сначала прочитай
> [docs/EVALUATION.md](docs/EVALUATION.md) и [docs/SECURITY.md](docs/SECURITY.md).

## Быстрый старт

```bash
npm ci
npm run example          # полное демо в локальной песочнице: создание → активация → 2 перевода
npm run create-wallet    # настоящий кошелёк (testnet): выводит адрес и сид-фразу из 79 слов
```

Дальше отправь ≥ 1 TON на выведенный адрес и:

```bash
TO=<адрес> AMOUNT=0.1 npx blueprint run transfer --testnet --tonconnect
npx blueprint run status --testnet --tonconnect
```

Первая операция сама активирует (задеплоит) кошелёк. Для mainnet: `NETWORK=mainnet npm run create-wallet`.

## Плюсы и минусы

| ✅ | ❌ |
| --- | --- |
| Постквантовая защита: только SHA-256 | ~0.22–0.27 TON за операцию (в 50–100 раз дороже W5) |
| Работает в TON уже сейчас (~600k газа < лимита 1M) | 128 подписей на дерево, нужно вовремя делать ротацию |
| Любое исходящее сообщение, защита от повторов | Атака на комиссии: поддельные/просроченные сообщения тратят баланс |
| Режим релеера (gasless), ротация ключей | Не поддерживается Tonkeeper / TON Connect, нестандартный XMSS |
| SDK, создание в 1 команду, сид-фраза, тесты | Нет аудита; 1 сообщение за транзакцию; нет mode 128 |

Главные правила: **последний лист дерева — только для ротации** (иначе средства заморозятся
навсегда), подписывать с одного устройства, разные ключи для testnet и mainnet, не держать на
кошельке больше, чем готов потерять.
